## 主动联系前端统计修复

### 需求
- 主动联系功能本身正常，但前端“点开人数”经常显示为 0 或 1，和实际主动联系点开的候选人数不一致。
- 只修复前端统计数据，不影响主动联系、消息处理、CDP、agent、浏览器操作。

### 问题原因
- 主动联系报告会把点开人数写入 `state.counts.opened / openedCandidates`。
- 部分主动联系报告没有逐个候选人的 `results` 明细，例如真实报告里 `openedCandidates=5`、但 `results=[]`。
- Web 端发现本地深度记录后，优先按候选人明细去重统计，忽略了这类只有汇总 counts 的主动联系报告，导致“点开人数”显示偏低。

### 修改
- `patchwork-recruit-gpt/server/legacy-parts/server.part002.js`
  - 新增主动联系 count-only 报告汇总兜底。
  - 从 `recruiter_batch_reports*.json` 读取 `opened / openedCandidates / proactiveOpened` 和 `greeted / proactiveGreeted`。
  - 合并指标时采用 `max(明细统计, 报告汇总)`，避免重复叠加。
- `patchwork-recruit-gpt/server/legacy-parts/server.part000.js`
  - BOSS 摘要接口、通用平台摘要接口返回前合并主动联系汇总 counts。
  - 自动化详情页顶部指标同样合并主动联系汇总 counts。

### 验证
- 已用服务器真实报告验证：`results=[]` 但 `state.counts.opened=5/openedCandidates=5` 的主动联系报告，会补齐到前端 `proactiveOpened=5`。
- 主入口语法检查通过：`node --check patchwork-recruit-gpt/server.js`。
- 已部署到服务器并重启 `RecruitAgentWeb8765`。
- 服务器接口验证通过：
  - `/api/boss-automation/summary?accountId=boss_b&date=2026-06-18&force=1` 返回 `proactiveOpened=5`。
  - `/api/boss-automation/details?accountId=boss_b&date=2026-06-18&force=1` 返回 `proactiveOpened=5`。
- 未改动主动联系执行流程、筛选规则、发送动作、消息处理流程。
