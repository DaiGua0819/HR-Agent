## 飞书面试问题文档空白修复
### 问题
- 面试中心点击“生成问题并同步飞书”后，飞书文档能创建成功，但打开文档正文为空。
- 服务器数据库中已有记录显示：
  - `feishuDoc.contentSynced=false`
  - `contentError=field validation failed`
- 根因是写入飞书 Docx block 时，系统把 Markdown 标题行也按普通 `text` block 写入；飞书 Docx API 对标题 block 要求使用 `heading1`、`heading2`、`heading3` 等字段，导致整批正文写入被接口校验拒绝。
- 旧逻辑只把错误放在 `feishuDoc.contentError`，前端仍显示“已创建”，容易误以为同步成功。

  - 将 `#`、`##`、`###` 等 Markdown 标题转换为飞书对应的 heading block 字段。
  - 普通正文继续使用 text block。
  - 长段落按长度拆分，避免单个 block 过长。
  - 正文写入改为分批插入，并带 `index`。
  - 新增 `syncInterviewDocumentContent()`，用于已有文档正文未同步时补写。
- 修改 `patchwork-recruit-gpt/server/features/interview-center/index.js`：
  - 文档创建成功但正文写入失败时，不再标记为 `prepared`，改为 `prepared_local`。
  - 写入失败会写入运行日志，并保留飞书接口 payload。
  - 已有 `contentSynced=false` 的文档再次准备时会尝试补写正文。
- 修改前端：
  - `patchwork-recruit-gpt/src/interview-center/app.js`
  - `patchwork-recruit-gpt/src/interview-center/styles.css`
  - `patchwork-recruit-gpt/interview-center.html`
  - 飞书文档栏会显示“已创建，正文未同步”和错误原因。
  - 静态资源版本更新为 `20260617-interview-doc-sync-1`，避免浏览器缓存旧逻辑。
