# 项目交接记录使用说明

这个目录用于保存项目长会话后的交接快照。新会话开始时，先读取本目录最新快照，再继续处理。

## 新会话读取顺序

1. 读取本目录说明文档：`项目修改快照/YYYY-MM-DD-项目修改快照说明.md`
2. 读取最新日期快照：例如 `项目修改快照/2026-06-11-项目修改快照.md`
3. 执行只读检查：`git status --short`、`git log -5 --oneline`
4. 如涉及服务器，先确认快照里的服务器状态、备份路径、部署方式，不要直接覆盖。

## 每次修改后必须记录

对项目或服务器做修改后，优先在当天或当前阶段的同一个快照里追加记录，不要每一次小修改都新建一个 Markdown。只有跨天、进入新的大阶段、或需要单独交接一组重要变更时，才新建一个日期快照。

- 修改时间：本地时间和服务器时间如果不同要说明。
- 操作目的：为什么改。
- 修改内容：改了什么逻辑、加了什么、删了什么。
- 触碰文件：列出具体文件和目录。
- 部署动作：是否上传服务器、是否重启服务。
- 备份位置：服务器或本地备份路径。
- 验证结果：跑过哪些命令、接口、页面检查。
- 当前风险：未提交、未部署、待确认、不要处理的历史数据。

## 文件粒度规则

- 默认一个日期一个主快照：例如 `2026-06-11-项目修改快照.md`。
- 同一天的多个小改动写进同一个 Markdown 的“修改记录”表格。
- 同一个任务链路的多次排查、修复、部署、验证应写在同一个快照里，保持上下文连续。
- 只有当变更跨天、范围很大、或用户明确要求单独记录时，才新建新的 Markdown。

## 安全规则

- 不在本目录记录明文密码、API Key、Cookie、Token。
- 可以记录服务器地址、服务端口、任务名、备份路径。
- 部署前先备份服务器文件。
- 不要清理历史简历、日志、备份，除非用户明确要求。
